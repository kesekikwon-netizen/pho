# R10 연결 수정 계획 (0.1.33, 측량 전용)

## 0. 전제
- 대상: 이 앱(`kr.archsurvey.field` 0.1.33)과 Trimble R10. SmartTopo C 에서는 같은 R10 이 정상 동작.
- 범위: 측량만 — 위치(GGA) 수신 → VRS 보정(RTCM) 전달 → 고정해 → 측점 저장. 기울기·전자기포·고급 기능 제외.
- 근거로 쓰는 것: 이 앱 코드, 폰에서 읽은 기록(adb), 표준 블루투스 SPP·NMEA·RTCM, Trimble 공개 문서.
- 쓰지 않는 것: 다른 회사 앱의 디컴파일 코드·통신 바이트·SDK·라이선스 정보(복사·우회 모두 금지).

## 1. 확인된 사실
| 사실 | 근거 |
|---|---|
| R10 은 GGA 를 받다가 1~2분마다 세션이 다시 시작됨. R10 에 쓰는 것은 RTCM 뿐 | `device/DeviceProfile.kt` 현장 메모(2026-10-11) |
| 보정 쓰기가 3초(`writeStallMs`) 막히면 세션을 끊고 다시 연결 | `engine/LinkSupervisor.kt` 워치독(수정 전) |
| R10 은 BR/EDR(클래식 블루투스), 페어링 기록의 광고 UUID 는 `0x1103` 하나(SPP `0x1101` 없음) | 폰 `dumpsys bluetooth_manager`(2026-10-11) |
| 폰에 설치된 앱은 0.1.32(64h 자동설정 없음). 0.1.33 의 R10 실기 시험 기록 없음 | 폰 `dumpsys package`, `BUILD_STATUS.md`·`FIELD_CHECKLIST.md` |
| SmartTopo 는 Trimble 라이선스 드라이버로 통신한다(구조 수준). 내부 동작은 이 계획의 근거로 쓰지 않음 | APK 구성(라이선스 드라이버 포함) |

## 2. 가설과 확인 방법
| 번호 | 가설 | 확인 방법(진단 기록) |
|---|---|---|
| H1(유력) | 수신기가 RTCM 을 안 받아 쓰기가 막힘 → 3초 뒤 세션 끊김 → 다시 연결해도 같은 자리에서 막힘 | `진단 세션 종료 BT-142`, 수정 뒤에는 `진단 RTCM 전달 막힘` |
| H2 | R10 블루투스 포트 입력(Input)이 보정을 받지 않는 설정 | 위치는 오는데 BT-142 안내가 계속, 고정해 없음 |
| H3 | R10 블루투스 포트 NMEA 출력 꺼짐, 64h 자동설정 실패 | `진단 R10 자동설정 결과=ALL_NAK/NOT_FOUND`, BT-130 |
| H4 | 그 밖의 이유(수신기가 연결을 끊음, 전원·거리) | `진단 세션 종료 BT-140/BT-123` 등 |

H1 만으로도 메모의 증상(위치는 오는데 1~2분마다 재시작)을 설명할 수 있다. 확정은 실기 시험(T2)으로 한다.

## 3. 작업
- [x] **T1** 브랜치 `fix/r10-rtcm-stall`
  - 위치(NMEA)가 계속 오면 보정 쓰기가 막혀도 세션을 유지하고 보정 전달만 멈춘다. 쓰기가 풀리면 막힌 동안 쌓인 보정은 버리고 새 보정부터 보낸다. 위치까지 끊기면 예전처럼 새 연결(`LinkSupervisor.kt`).
  - 연결 화면 안내 BT-142 「보정 데이터가 수신기에 들어가지 않아요」(수신기 블루투스 포트 Input: Auto) + 진단 「RTCM 전달 막힘/재개」(`ConnectionModel.kt`).
  - 페어링 기록에 SPP(`0x1101`) 없이 다른 UUID 만 있으면 그 UUID 로 먼저 연결(R10: `0x1103`). 기록이 비거나 SPP 가 있으면 예전 순서(`BtCompat.kt` `planAttempts`).
  - 단위 시험 5개 추가, 기존 쓰기 막힘 시험은 「위치도 끊긴 경우」로 조정. 전체 838개 중 832개 통과(실패 6개는 V월드 내장키가 빈 템플릿이라 생기는 기존 실패).
  - **실기 미검증.**
- [ ] **T2** 실기 시험
  - 사전 조건: 기존 앱(0.1.32)·SmartTopo 완전 종료(R10 블루투스 포트는 한 번에 한 앱), 같은 VRS 아이디 동시 사용 금지(403), 하늘이 트인 곳, 폰과 R10 2 m 안.
  - 시험 빌드: `kr.archsurvey.field.debug`(0.1.33-debug, 기존 앱과 따로 설치).
  - 순서: R10 켜기 → 시험 빌드로 R10 연결 + VRS 켬 → 5분 이상 유지 → 화면의 고정해 여부 기록.
  - 수집: `adb shell run-as kr.archsurvey.field.debug cat files/crash-log.txt` — `진단 세션 종료`, `진단 R10 자동설정`, `진단 RTCM 전달 막힘/재개`, `NMEA 활성화` 줄.
- [ ] **T3** T2 결과별 처리
  - 위치 없음(BT-130, `ALL_NAK`/`NOT_FOUND`): R10 웹 UI 에서 그 블루투스 포트 NMEA(GGA·GST 1 Hz) 켜고 「Maintain configuration when connection dropped」 체크 → 다시 시험. 64h 추가 전송은 늘리지 않는다.
  - 위치는 오는데 BT-142: R10 웹 UI 에서 그 포트 Input: Auto → 다시 시험. 앱에서 입력 설정까지 하려면 Trimble 공개 문서에서 명령을 확인한 뒤에만 추가.
  - 다른 이유로 끊김(H4): 세션 종료 진단의 오류 코드·지속 시간·RTCM 송신량을 보고 원인별로 수정.
  - 연결 단계 실패(BT-120/124): 저장된 연결 방식, 페어링 다시 하기, 권한·검색 중지 확인.
- [ ] **T4** 회귀·머지
  - 단위 시험 전체(V월드 실키를 넣고), lint.
  - 기존 lint 오류 `engine/Engine.kt:127` `silentStrategies.clear()`(API 24, minSdk 21) 처리 결정.
  - main 머지.

## 4. 비목표
- 기울기·전자기포·정밀 측위 API, Trimble SDK 연동, 라이선스 우회, 다른 앱 코드·바이트 복사.

## 5. 성공 기준
- R10 연결 → 위치 수신(STREAMING) → VRS 보정 수신(RECEIVING) → 고정해 → 측점 저장.
- 5분 이상 세션 유지(세션 종료 진단 없음).

## 6. 정리할 것
- 브랜치 `fix/r10-insecure-first`(커밋 c04e9b9, 다른 작업 폴더): 다른 앱 디컴파일 내부 순서를 근거로 한 커밋이라 합치지 않는다. 연결 순서는 T1 의 광고 UUID 기준으로 통일.
- 이전 계획서 `r10-smarttopo-fix-plan.md`(같은 작업 폴더, 커밋 안 됨)는 디컴파일 경로·줄 번호가 들어 있어 이 저장소에 넣지 않는다.
